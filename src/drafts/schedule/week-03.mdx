### 3-1 View Source — Context Discussion

### Learning objectives

{/* By the end of this session you will be able to: */}
1. Apply five design fundamentals from Ch 2 Context to critique and sketch a redesign of a poorly designed website.
2. Use browser DevTools to temporarily modify a live website's content, demonstrating that design choices are not neutral.
3. Caption each DevTools modification to articulate what the hidden design choice reveals about power or intent.

📖 **Read before class:** Ch 2 Context, pp. 45–51

**Group — "Redesign This" Sketch Sprint**
Teams of 3 receive a screenshot of a poorly designed website. Sketch a redesigned layout on paper in 15 min applying the five design fundamentals from the reading. Present your before/after with rationale.

**Individual — DevTools Interventions**
Use DevTools to temporarily modify 3 real websites: change a headline, swap a color, hide an ad, alter a price. Screenshot your modifications. Caption each: "I changed ___ to reveal ___."

> 🛠 **Next class:** Module 2.1, pp. 52–57 · 📌 Start [View Source](https://github.com/omundy/dig245-view-source) or [CSS Self-Portrait](https://github.com/omundy/dig245-css-self-portrait)

### 3-2 Design Fundamentals

### Learning objectives

{/* By the end of this session you will be able to: */}
1. Identify and rate contrast, alignment, repetition, proximity, and visual hierarchy in real websites using annotated screenshots.
2. Write three CSS selectors for a single element (by type, class, and complex rule) and evaluate trade-offs in specificity and maintainability.
3. Distinguish between design choices made for aesthetics vs. those made to guide user behavior or carry ideology.

🛠 **Work during class:** Module 2.1 *Design Fundamentals* (pp. 52–57)

**Individual — Design Principles Audit**
Open 3 websites. For each, annotate a screenshot (Figma or paper) identifying: contrast, alignment, repetition, proximity, visual hierarchy. Rate each principle 1–3. What pattern do you see across all three?

**Pair — Selector Challenge**
Each partner writes 3 CSS selectors targeting the same element: one by element type, one by class, one more complex (descendant, pseudo-class). Which is most maintainable? Which is most specific? Discuss the trade-offs.

> 🛠 **Next class:** Module 2.2, pp. 58–73

### 3-3 HTML & CSS

### Learning objectives

{/* By the end of this session you will be able to: */}
1. Build a linked external CSS stylesheet that establishes a coherent visual identity through color palette, typography, and spacing.
2. Give and receive "Glow and Grow" peer critique using design intent and code organization as evaluation criteria.
3. Articulate how specific CSS decisions (color, font, spacing) communicate meaning beyond decoration.

🛠 **Work during class:** Module 2.2 *HTML & CSS* (pp. 58–73)

**Individual — CSS Styling Exercise**
Follow Module 2.2 to add CSS to your page or [CSS Self-Portrait](https://github.com/omundy/dig245-css-self-portrait). Focus: custom color palette (3 colors), 2 font choices with sizing, spacing with padding/margin. Separate linked stylesheet — no inline styles.

**Group — View Source / CSS Self-Portrait Critique**
Share your drafts. Give each other feedback on: (1) Does the CSS communicate a design intent? (2) Is the code organized? Use "Glow and Grow": one strength, one specific growth area.

> 🛠 **Next class:** Module 2.3, pp. 74–81
