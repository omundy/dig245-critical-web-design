### 13-1 Generative Visualization

### Learning objectives

{/* By the end of this session you will be able to: */}
1. Build a generative art piece demonstrating arrays of values, a visual rendering loop, a random element, and a rule-based element.
2. Modify a peer's generator by changing exactly 3 parameters and document how each change shifts the aesthetic output.
3. Explain the relationship between parameter choices and aesthetic results in a generative system.

🛠 **Work during class:** Module 8.2 *Generative Arp Visualization* (pp. 269–279)

**Individual — Module 8.2 Coding Exercise**
Build the generative art piece from Module 8.2. Must demonstrate: arrays of values, a loop generating visual output, at least one random element, at least one rule-based element.

**Pair — Variation Challenge**
Take your partner's generator and change exactly 3 parameters to produce a meaningfully different aesthetic. Document what changed and what shifted visually. Present both versions side-by-side.

> 🛠 **Next class:** Module 8.3, pp. 280–289

### 13-2 SVGs & Color Arrays

### Learning objectives

{/* By the end of this session you will be able to: */}
1. Generate an SVG pattern programmatically using JavaScript, driven by a color array that produces a different result on every page load.
2. Use arrays to control visual output at scale — color, position, size, or repetition — rather than coding each element individually.
3. Pitch a Regenerative project concept and give structured peer feedback on system clarity, aesthetic goal, and technical risk.

🛠 **Work during class:** Module 8.3 *SVGs and Color Arrays* (pp. 280–289)

**Individual — SVG & Color Arrays**
Complete Module 8.3 exercises: generate an SVG pattern programmatically using JavaScript. Use a color array (at least 5 colors) to drive element colors. Output should look different on every page load.

**Group — Regenerative Project Concept Share**
Share your concept for the [Regenerative](https://github.com/omundy/dig245-regenerative) project. Peer feedback using 3 questions: (1) Is the generative system clear? (2) What is the aesthetic goal? (3) What's technically risky and needs prototyping first?

> 📚 **Before next class:** Read Ch 9 Context, pp. 291–298

### 13-3 Data Tracking — Context + DevTools

### Learning objectives

{/* By the end of this session you will be able to: */}
1. Use DevTools Network tab to catalog and count third-party trackers across 5 different website categories.
2. Identify the companies operating trackers across multiple site categories and explain what business model their presence reveals.
3. Write a 150-word analysis connecting tracker patterns to the business model of a specific website, referencing Ch 9 Context.

*(Last class before Thanksgiving.)*

📚 **Read before class:** Ch 9 Context, pp. 291–298
🛠 **Work during class:** Module 9.1 *DevTools and Data* (pp. 299–308)

**Group — Personal Data Audit**
Following Module 9.1: use DevTools Network tab to catalog every third-party request on 5 types of websites — (1) news, (2) shopping, (3) social media, (4) health/medical, (5) government. Count trackers, identify companies. Which category surprises you most?

**Individual — Business Model Analysis**
Write 150 words: What pattern do the trackers reveal about the business model of your most-tracked site? Who profits from your visit? What data is collected and why? Reference the Ch 9 context.

> 📚 **Over break:** Read Ch 10 Context, pp. 323–331
