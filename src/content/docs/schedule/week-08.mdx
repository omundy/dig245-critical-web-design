### 8-1 Usability & Forms — Context Discussion

### Learning objectives

{/* By the end of this session you will be able to: */}
1. Apply Nielsen's 10 Usability Heuristics to evaluate a real website, rating 5 violations by severity (0–4) with screenshot evidence.
2. Observe a live usability test using the think-aloud protocol and document unexpected user behaviors.
3. Distinguish between designing for your own preferences and designing for an observed user's actual mental model.

📖 **Read before class:** Ch 5 Context, pp. 153–161

**Individual — Heuristic Evaluation**
Apply [Nielsen's 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/) to a website you use regularly. Find 5 specific issues, rate each severity 0–4, document with screenshots. Which heuristic is violated most often?

**Group — Live Usability Test**
Following Module 5.1 protocol: one volunteer "thinks aloud" attempting a task on a real website. Everyone else observes silently and documents issues. Debrief: What surprised you about watching someone use a familiar site?

> 🛠 **Next class:** Module 5.1, pp. 162–165 · 📌 Start Usability Test project

### 8-2 Usability Testing & JS Data Types

### Learning objectives

{/* By the end of this session you will be able to: */}
1. Declare and test JavaScript variables of multiple data types, including edge cases (undefined, null, NaN).
2. Write a function that correctly handles different input types and explain how JavaScript type coercion can produce unexpected results.
3. Predict the output of JS expressions involving type coercion before running them, and document where predictions were wrong.

🛠 **Work during class:** Module 5.1 *Usability Testing* (pp. 162–165) + Module 5.2 *JavaScript Data Types* (pp. 166–177)

**Individual — Data Type Lab**
Complete Module 5.2 exercises in [Codepen](https://codepen.io): declare variables of each type, log their types, write a function that handles different types correctly. Include at least one edge case (undefined, null, NaN).

**Pair — "Guess the Type" Game**
Partners take turns writing a JS expression without running it. The other guesses: What type? What value? Keep score. Debrief: where did type coercion surprise you?

> 🛠 **Next class:** Module 5.3, pp. 178–184

### 8-3 JS, Bootstrap & Web Forms

### Learning objectives

{/* By the end of this session you will be able to: */}
1. Build a web form with multiple input types, client-side JavaScript validation, and Bootstrap styling that is fully keyboard-navigable.
2. Audit a real web form using WAVE and keyboard-only navigation to identify missing labels, error states, and tab order issues.
3. Propose a specific fix for each accessibility issue found in a real-world form audit.

🛠 **Work during class:** Module 5.3 *JavaScript, Bootstrap and Web Forms* (pp. 178–184)

**Individual — Form Build**
Following Module 5.3: a form with text input, email, dropdown, checkboxes, radio buttons, textarea, and submit. Add client-side JS validation. Style with Bootstrap form classes. Must be fully keyboard-navigable.

**Group — Form Accessibility Audit**
Audit 2 forms on real websites using [WAVE](https://wave.webaim.org) + keyboard-only navigation. Document: missing labels, unclear error states, tab order issues. Present your worst offender with a specific fix for each issue found.

> 📚 **Codecademy (due Mon):** [Introduction to JavaScript](https://www.codecademy.com/learn/introduction-to-javascript) — "Functions" + "Scope"
