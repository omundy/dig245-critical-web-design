## Week 1 — Aug 24–28
*Ch 0: Introduction · Ch 1: Networks (context)*

### 1-1 Course Introduction

**Learning objectives:** By the end of this session you will be able to:
1. Identify at least 2 examples of critical web design and articulate their critical intent in writing.
2. Distinguish between ordinary web design and critical design using specific formal and conceptual criteria.
3. Define "critical design" collaboratively and apply that definition to unfamiliar examples.

🛠 **Work during class:** Hello, World! Start assignment using Codepen.

**Individual —** Browse the [Critical Web Design Index](https://criticalwebdesign.github.io/index/). Pick 2 examples you find surprising or compelling. Write: What's the critical intent? What design choices make it effective?

**Group — What makes design "critical"?**
Table groups share their examples. Debrief: What do these pieces have in common that separates them from ordinary design? Build a working definition together. Share in class and return to it at the end of the semester.

**Learning objectives:** By the end of this session you will be able to:

### 3-2 Design Fundamentals

**Learning objectives:** By the end of this session you will be able to:
1. Identify and rate contrast, alignment, repetition, proximity, and visual hierarchy in real websites using annotated screenshots.
2. Write three CSS selectors for a single element (by type, class, and complex rule) and evaluate trade-offs in specificity and maintainability.
3. Distinguish between design choices made for aesthetics vs. those made to guide user behavior or carry ideology.

🛠 **Work during class:** Module 2.1 *Design Fundamentals* (pp. 52–57)

**Individual — Design Principles Audit**
Open 3 websites. For each, annotate a screenshot (Figma or paper) identifying: contrast, alignment, repetition, proximity, visual hierarchy. Rate each principle 1–3. What pattern do you see across all three?

**Pair — Selector Challenge**
Each partner writes 3 CSS selectors targeting the same element: one by element type, one by class, one more complex (descendant, pseudo-class). Which is most maintainable? Which is most specific? Discuss the trade-offs.

> 🛠 **Next class:** Module 2.2, pp. 58–73
